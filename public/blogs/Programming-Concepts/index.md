> * Rust 是**静态**并且**强类型**的**编译型**语言，追求极致的安全性
> * Rust 编程时很难陷入因为数据以未预料或未考虑的方式移动而出现奇怪bug的情况

## Static and Strong

* 静态类型：所有数据的类型在**编译时**已知。错误检测较早，运行速度通常较快
* 动态类型：只有在**运行时**才知道数据的类型。一个变量每次运行时可以持有不同类型的数据
* 强类型：对可以赋值给变量的数据类型**强制执行严格的规则**。类型转换必须显式进行，很少有隐式转换
* 弱类型：对数据类型的赋值**约束少或者无约束**

## Compiled vs Interpreted

* 编译型语言：需要编译步骤（编译器）来**生成可执行文件**，如 C/C++、Rust、Go
    * 编译大型项目耗时较长，需要为不同平台重新编译，且修改后需重新编译测试
    * 只需二进制文件和必要的库即可执行
    * 通常更快且更节省内存
* 解释型语言：无需编译，代码在执行时**由解释器逐行解释执行**，如 Python、JavaScript、Ruby
    * 无需编译，但任何有解释器的平台都可运行，且修改后可直接测试
    * 需要安装解释器才能执行
    * 通常更慢且存在解释开销，会占更多内存
* 中间方法：会先将源代码编译为一种**与平台无关的中间语言**，在运行时通过一个虚拟机（Common Language Runtime, CLR）使用即时编译器（Just in Time, JIT）将中间语言编译为本地机器码执行，如 C#、Java
    * **CLR还负责内存管理、垃圾回收、安全性及其他运行时服务**
    * 在具备比较高执行效率的同时，又有一定的跨平台的灵活性

## Stack vs Heap

![](/blogs/Programming-Concepts/0e101f5c15483cb7.png)

* 栈内存：LIFO 后进先出，访问速度较快，所有数据必须是已知的**固定大小**
* 堆内存：组织性较差，访问速度较慢，但允许存储**未知大小或可变大小**的数据

在堆内存申请空间时，一般都会在栈内存上创建一个指向堆内存相应位置的指针变量。不当地使用内存会带来双重释放以及内存泄漏问题

**所有权是 Rust 中用于管理程序如何处理内存的一组规则**，在没有垃圾回收器时也可以帮助确保程序的内存安全
